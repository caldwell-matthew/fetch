# dd_reference — do not delete

Artifacts here are **unrecoverable if lost** and generated by nothing in `dd_scripts_mobile/`.
They sit outside `dd_tests_mobile/`, so `push` never touches them.

## `MOB.600_with_upload_steps.json`

A 21-step `MOB.600_Collector_Create_Asset` carrying the master copy of the only working
**`uploadFiles` step**. Its `bucketKey` points into Datadog's own storage and no API mints one
(trap 12): the step exists only because a human authored it in the Datadog UI. `DD_FORCE=1` on a
generator would destroy it, not recreate it.

**The key is portable.** Datadog re-namespaces it to the receiving test on push, so
`dd_tools.upload_steps()` copies the reveal + `uploadFiles` steps out of the live `MOB.600` JSON at
build time — one copy, and a build fails loudly if it goes missing.

**What it encodes:** the input is created by `useFileDialog` with `display:none` and appended to
`<body>`; it exists only while the photo modal is open; it is indistinguishable from three camera
inputs; its index is **3**, measured (render order predicts 1).

**To restore the recipe** — 🛑 never copy this file over the live test (the live one has 31 steps,
including `PROOF OF CREATION` and the bugs §34 server proof). Splice this file's reveal and
`uploadFiles` steps back into `dd_tests_mobile/MOB.600_Collector_Create_Asset.json` after
`Open the photo picker`, then `push`. `build_collector_tests.py` refuses to regenerate `MOB.600`
while an `uploadFiles` step is present.
